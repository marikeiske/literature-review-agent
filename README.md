# Literature-review agent with source tracing

*[Versão em português](README.pt-BR.md)*

An LLM agent that answers questions about a closed corpus of scientific papers and **cites the PDF
page behind every claim**. A deterministic verifier checks each citation, and nothing is saved
until a human approves it. Domain: heterogeneous computing for safety-critical avionics, where
every engineering claim must be traceable to its source.

Final project of TE-251 (ITA, 2026.2). The accompanying paper (IEEE format, in Portuguese) reports
the evaluation below.

## How it works

1. **Agentic RAG.** The model gets read-only tools (`buscar_trechos`, BM25 search over page
   snippets; `ler_pagina`; `listar_artigos`; `carregar_skill`) and decides what to read. A budget of
   4 tool calls per question stops search loops (`agente/harness.py`). The harness only runs tools
   on an explicit allow-list; any other name gets a permission error and nothing runs.
2. **One claim per line, with `[DocId p.N]`.** The system prompt requires a citation on every
   line, an explicit refusal ("Não consta no material aberto.") when the data is missing, and a
   correction ("A premissa não confere: …", with a citation) when the question's premise is false.
3. **Deterministic verifier** (`agente/verificador.py`, no LLM). Each line is marked as
   *traceable* (the cited page was read in this turn and its numbers appear on it), *number
   missing*, *page not read* (a fabricated citation), *refusal without reading*, or *no citation*.
   It is necessary, not sufficient: it does not check meaning.
4. **Human in the loop.** The web UI opens the cited PDF page next to the answer, with the numbers
   highlighted. The reviewer approves, asks for a correction or rejects; only approval writes a note
   to `fichamentos/` (`agente/hitl.py`). The reviewer is only called when there is a citation to
   approve; a correction keeps the pages already read.
5. **Stop reason in the trace** (`agente/parada.py`). Every turn ends with one of: *awaiting
   approval*, *goal met* (approved), *rejected*, *refusal* (nothing to approve, the human is not
   called), *handled failure* (no page was read: no claim is shown and the human is not called) or
   *limit*. The trace in `logs/` holds the question, tool calls, returned passages, answer and stop.

## Results (109 gold claims, 11 documents)

All numbers come from `resultados/resumo_numeros.md`, regenerated by `python resumo_avaliacao.py`.
Exact cited page vs. the human-reviewed gold set, agentic RAG, temperature 0 (runs of 20–26 Oct 2026):

| Model (provider) | Exact page | 95% CI (Wilson) | Cited an unread page |
|---|---|---|---|
| Nemotron 3 Ultra (Ollama Cloud) | 106/109 (97%) | 92–99% | 0 |
| GPT-OSS 120B (Groq) | 104/109 (95%) | 90–98% | 0 |
| GPT-OSS 120B (Ollama Cloud) | 104/109 (95%) | 90–98% | 0 |
| Gemma 4 31B (Ollama Cloud) | 103/109 (94%) | 89–97% | 0 |
| Gemini Flash-Lite (Google) | 99/109 (91%) | 84–95% | 0 |

- **No model cited a page it had not read** (the verifier would flag it).
- **Negative questions** (out of corpus, false premise, missing data, data only in a figure):
  12/12 by the automatic rule for every model above. A human reviewer checked every answer; with a
  binary rubric (a partial answer counts as a fail), Gemini scores 11/12 and the others 12/12.
- **Does the refusal hold every time?** Each negative question run 5 times on Gemma 4 31B:
  pass^5 = 12/12 (95% CI 76–100%, automatic rule). Every question stopped the same way in all 5
  attempts: 30 awaiting approval (premise corrections and one refusal that cites the closest fact),
  20 refusals and 10 handled failures (two out-of-corpus questions where no page was read).
- **The course's own case** (Lesson 11 `test.jsonl`, excerpt inside the message, base model without
  LoRA, 5 attempts): Gemma 4 cited a paragraph in the excerpt in 14/14 and refused in 6/6, every time.
- **Suites:** 92 claims every model got right form the regression suite; the 17 that at least one
  model missed form the capability suite (`resultados/suites.json`).
- **RAG vs. whole paper in the prompt:** no significant difference for Gemma or Gemini
  (McNemar p = 0.73 and 0.39). For GPT-OSS, RAG was better (95% vs. 87%, p = 0.035): with the
  whole paper, it found the right passage but cited the neighbouring page. Long context also costs
  about 3× more input tokens.
- **Model ranking:** the confidence intervals overlap; with 109 items, none of the differences
  between models is significant (best vs. worst p = 0.065).

Limitations and risks (data sent to third-party providers, indirect prompt injection, a single gold
set annotator) are discussed in the paper's AI Assurance section and in
[README.pt-BR.md](README.pt-BR.md#segurança-e-privacidade).

## Quick start (Windows)

```
py -3.11 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env          (add at least one free API key)
python -m agente.corpus         (indexes the PDFs in corpus/, see corpus/FONTES.md)
python app.py                   (web UI at http://127.0.0.1:8765)
```

Or double-click `abrir_agente.bat`. Free providers only: Groq, Google AI Studio, OpenRouter
`:free` models and Ollama Cloud (free plan).

## Evaluation

```
python avaliar.py groq                       109 gold claims (resumes where it stopped)
python avaliar.py groq --condicao contexto   no RAG: whole paper in the prompt
python avaliar.py groq --negativas           12 questions whose right answer is to refuse or correct
python avaliar.py groq --negativas --repeticoes 5   each one 5 times: pass^5 (the refusal must hold every time)
python avaliar.py groq --suite capacidade    only the claims some model got wrong (capability suite)
python avaliar.py groq --suite regressao     only the claims every model got right (regression suite)
python -m experimentos.aula11_norma groq     the course's test.jsonl (Lesson 11) with a code grader
python resumo_avaliacao.py                   all numbers, CIs, McNemar, pass^k, rubric, path and suites
```

The Lesson 11 dataset is course material and is not in the repository: put `train.jsonl`,
`valid.jsonl` and `test.jsonl` in `dados/aula11/` (ignored by git).

Since 26 Oct 2026, every run logs the git commit, system-prompt hash and gold-set hash to `resultados/execucoes.jsonl`.
The PDFs are not in the repository (copyright; one is not for redistribution): `corpus/FONTES.md`
lists each source and its SHA-256, and `python corpus_fontes.py --conferir` checks your copies.

## Daily check until the presentation

`teste_diario.py` runs once a day (5–12 Nov 2026): the code tests, 5 gold claims, 1 negative question
and 1 free question, different each day, so a free model that changes without notice breaks the day it
happens, not during the demo. `scripts/agendar_teste_diario.ps1` schedules it on Windows; the result
goes to `logs/monitoramento/resumo.md` (outside git).

## Development

```
pip install -r requirements-dev.txt
python -m playwright install chromium    (once, for the UI tests)
pytest            verifier, harness stops and allow-list, page parsing, local-server security, statistics, end-to-end UI
ruff check .
```

GitHub Actions runs tests, lint and `pip-audit` on every push (pinned to `ubuntu-24.04`: on
`ubuntu-latest`, now 26.04, Playwright 1.56 cannot install Chromium). The harness tests
(`tests/test_harness.py`) drive the loop with a fake model, without network. The UI tests (`tests/ui`, Playwright) run the
server on a temporary copy of the project with synthetic PDFs, so they never touch real files. `tests/ui/test_acessibilidade.py` runs axe-core (WCAG 2.1 AA, light and dark)
on every tab and checks keyboard and focus behaviour. Project rules for coding agents are in
`AGENTS.md`.

## Security

The local server only listens on `127.0.0.1` and rejects requests from other origins (Host, Origin and
JSON content type are checked), which blocks cross-site requests and DNS rebinding. Agent tools are
read-only. See `seguranca.py` and `tests/test_seguranca.py`. Optional phone access (`MESA_REMOTO=1`)
adds a second listener bound only to the machine's Tailscale address, gated by an access code kept in `.env`
(`tests/ui/test_remoto.py`).
